<details><summary>Performance (2)</summary>

- **projectViews**: load project view asset lists faster ([#7801](https://github.com/kobotoolbox/kpi/pull/7801))
    > <!-- 📣 Summary -->
    > Project views load their list of projects much faster, especially views
    > that cover every country.
    > 
    > <!-- 📖 Description -->
    > Opening a project view used to get slower as the number of projects it
    > covers grew, because the list was counted and sorted in full every time,
    > and some project details were looked up one project at a time. The list
    > now comes back in a few steps whatever its size, with the same projects
    > in the same order. The project view list API no longer returns the total
    > number of projects (`count`); the `next` link still pages through the
    > results.
    > 
    > ### 👷 Description for instance maintainers
    > A migration adds two indexes on the projects table: one for the default
    > sort of project lists, one for the sort by creation date. They are
    > created concurrently, without locking the table.
    > 
    > If `SKIP_HEAVY_MIGRATIONS` is set, the migration only prints the SQL
    > below; run it in PostgreSQL directly, otherwise project views stay slow:
    > 
    > ```sql
    > CREATE INDEX CONCURRENTLY IF NOT EXISTS "asset_survey_default_order_idx" ON "kpi_asset" USING btree ((array_position(ARRAY['deployed', 'draft', 'archived']::varchar[], "_deployment_status")), "date_modified" DESC, "id") WHERE ("asset_type" = 'survey' AND NOT "pending_delete");
    > CREATE INDEX CONCURRENTLY IF NOT EXISTS "asset_date_created_id_idx" ON "kpi_asset" USING btree ("date_created" DESC, "id");
    > ```

- **projectViews**: stop querying organizations per owner when checking permissions ([#7816](https://github.com/kobotoolbox/kpi/pull/7816))
    > <!-- 📣 Summary -->
    > Project views load their list of projects faster for users whose view
    > does not give access to submissions.
